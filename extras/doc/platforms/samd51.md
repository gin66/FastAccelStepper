# Microchip SAMD51 Platform

[Back to README](../../../README.md) | [Platform index](../hardware.md) | [Design notes](../samd51/CONTEXT.md)

The SAMD51 port was contributed by Loriland (see
[issue #317](https://github.com/gin66/FastAccelStepper/issues/317)).

## Usage limits

* one stepper per TCC instance: 3 steppers on SAMD51G, up to 5 on SAMD51J/N/P
* step pin must have a TCC waveform output in the board's variant table;
  direction/enable can be any output pin
* one overflow interrupt per step; pulse edges are hardware-timed, so step timing
  is exact regardless of interrupt latency
* Steppers' command queue depth: 32
* SAMD21 is not supported (compile error)
* requires an Arduino SAMD51 core (uses the variant pin table); tested with the
  Adafruit SAMD core

## Implementation

The step pin's TCC runs in normal PWM mode with buffered registers: `PERBUF`
holds the next step interval and `CCBUF` the pulse width, so pulse edges are
generated by hardware and are tick-exact regardless of interrupt latency. One
overflow interrupt per step decrements the current queue entry and stages the
next command at command boundaries — the same design as the AVR port, but with
the timer's double buffering removing the edge-timing race.

The timebase is exactly 16 MHz (DFLL48M divided by 3) on a dedicated generic
clock generator, matching the AVR/ESP32/Pico tick rate so the precomputed ramp
constants apply. The ~4 ms ramp tick (`manageSteppers()`) runs from a plain TC
instance. Defaults can be overridden at compile time if your project claims these
peripherals:

```
-DFAS_SAMD_GCLK_GEN=6         // generic clock generator for the 16 MHz timebase
-DFAS_SAMD_RAMP_TC=3          // TC instance for the ramp tick (TC0 is used by tone())
-DFAS_SAMD_PULSE_WIDTH_US=2   // step pulse high time
```

The implementation contains a workaround for silicon erratum DS80000748 (2.20.1):
clearing `STATUS.PERBUFV`/`CCBUFV` releases SYNCBUSY before the buffer registers
are actually restored, so the flags are cleared twice with SYNCBUSY waits —
otherwise a write to `PER` right after an aborted buffered update can wedge the
synchronization bridge permanently.

See the [SAMD51 design notes](../samd51/CONTEXT.md) and the detailed
[per-step ISR](../samd51/0001-tcc-npwm-per-step-isr.md) and
[16 MHz timebase](../samd51/0002-16mhz-timebase-via-gclk.md) documents.
